# PLAN-release-update — the clean Mac kept one cluster while the product changed

**S36 / session 8C — cut 23 August 2026; retired 26 August as an evidenced
stop.** Replacement A earned one exact private P2–P5 authority, but the
Apple-supported final macOS 27 restore-image resolver failed its initial call
and two bounded repeats before any IPSW, VM, Installer or guest cell existed.
Trusted lifecycle acceptance was not earned. The execution contract below is
retained as the authority for what was attempted and what remains unclaimed.

The VM/admin/network gate has tripped, but execution starts at one harder
authority gate: the private S35 P5, sidecar, retained finalizer source, and
evidence roots named at closeout are no longer present on the current
filesystem. Their hashes remain historical evidence, not usable bytes.
Restore and reverify that exact authority, or obtain a separate founder ruling
for each replacement signed and notarized lineage. Never rebuild from a hash
and call it the old artifact.

**Founder replacement ruling — 23 August 2026.** Exact historical A could not
be restored. The founder authorized a new two-release lineage, but did not yet
authorize its credentialed execution:

- replacement A is product/host `0.0.2`, helper `1.0.2`;
- replacement B is product/host `0.0.3`; its helper remains `1.0.2` only when
  the complete signed A helper component is carried forward byte-for-byte and
  is not re-signed; any helper drift stops for a new `1.0.3` ruling;
- A and B each require one separately checkpointed Developer ID/notary
  submission, for exactly two possible future submissions; and
- identity resolution, signing, timestamping, profile use, submission and
  stapling remain stopped until this offline implementation is reviewed,
  committed, pushed, synchronized, and a final varied-root U1 is earned.

The replacement ruling supersedes Gate A-LOST as the selected route. It does
not make historical S35 bytes available, does not authorize reconstructed
history, and does not broaden VM, live-host, publication, Keeper, or credential
authority.

S36 may close only if one clean, vanilla Apple-sourced macOS 27 arm64 guest
proves all of the following from exact retained release authority:

1. a quarantined, Developer-ID-signed, Apple-notarized and stapled Reach

## Frozen product and transaction boundary

1. **State is never package or rollback payload.** User state, CA, keys,
   identities, registry, mesh intent, logs, prompts, output and model/cache
   remain outside both packages, the immutable rollback product and evidence.
2. **One selected login owner, one root road owner.** Installer lays immutable
   root-owned bytes. It does not choose a user, start reachd as root, mint a
   CA, read a home directory or apply mesh intent. The named login user binds
   the packaged canonical reachd. Mesh application is a later explicit guest
   administrator ceremony.
3. **One complete host unit.** Reachd and its seven adjacent bundles move as
   one unit. `/usr/local/bin/reachd` is only the canonical symlink; it receives
   no resource copy.
4. **Two component receipts remain real.** Host and helper are separately
   versioned and carried by one flat product installer. Default install and an
   attempted explicit choice deselection must both leave the exact two
   payloads and receipts. The known read-only S34 choice result is a question,
   not acceptance.
5. **Updates are fresh-inode, whole-product transactions.** Stop the exact
   login job; retain exact A package authority; install and verify one complete
   compatible B; reload the helper only through package/system-service
   authority if its installed bytes changed; then bind and start the same
   login owner. A mixed A/B product never serves.
6. **Rollback restores software, never state.** An explicit rollback may use
   only the retained exact trusted A parent and may not hand-copy extracted
   payload bytes. Ordinary downgrade remains refused by the first-class
   transaction path.
7. **Uninstall distinguishes ownership.** Package bytes, aliases, jobs,
   helper-owned routes/runtime and package receipts go. Login-owned cluster
   state, host key, registry, intent, logs and model/cache remain until a
   separately authorized state destruction.
8. **No automatic updater appears.** S36 may add a private acceptance driver
   and exact operator transaction commands. It does not add a feed, polling
   daemon, downloader, telemetry, account or silent install.
9. **Admin power is not a bypass.** No `-allowUntrusted`, Gatekeeper disable,
   SIP disable, ad-hoc fallback, signature-policy mutation, passwordless sudo,
   receipt fabrication or manual payload copy may turn a refusal into a pass.
10. **Keeper remains Held.** No Keeper target, Network Extension, ceremony,
    provisioning profile, profile-authority rider or device package enters
    this pass.

This section records the plan as originally cut. It is not executable

replacement implementation and checkpoints described after this historical

### Historical A — unavailable and not selectable

The preferred A is the exact historical S35 P5:

- product/host `0.0.1`, helper `1.0.1`;
- P5 SHA-256 `97397473…6389f`;

If historical A is restored, the default B design is:

- product and host `0.0.2` from one later synchronized source commit;
- helper remains `1.0.1` only if its complete payload is byte-identical to A;
  if helper payload changes for a real reason, use a separately consumed
  `1.0.2` and update compatibility truthfully;

Current release code intentionally freezes the first release and exact S34 U1
