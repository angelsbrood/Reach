# S84 durable host–client join

This opt-in local candidate composes the unchanged S82/S81 host and S83 client
with two additive same-module adapters and a Foundation/CryptoKit IPC contract.
Run `python3 run.py --repo /path/to/Reach` using Python 3.12 or later, the accepted
local dependency checkouts and Metal library. It performs offline native reconstruction, focused XCTest, and
separate-worker joins/deaths, then removes exact private source/build/journal roles.
All earlier source bytes and the 35 native composition outputs remain bound.
For convergence, `--test-filter` selects named tests; `--workers-only` and
`--worker-filter` reuse earlier tests and select worker cases. Filtered results
describe only the executed subset; unchanged earlier proof must be cited separately.

The host exports original context from verified ticket claims and its persisted
request and identity. Catalog incarnation is the namespace-stable host/store
anchor; child identity and exact request/provider bytes bind the upstream digest.
The surviving trusted supervisor freezes that authority and a fresh independent
client root/key before native publication. It marks root establishment before
launch, so any retry uses recovery. Missing established history remains unavailable;
neither a lost transport cursor nor a new root can replace it. Lost supervisor
configuration itself is outside this candidate's recovery promise.

Actual S81 first/count/commit/raw-byte/skip replay enters actual S83 storage. The
client witness is derived from the authenticated selected snapshot: stable receipt
revision/high/terminal plus length-prefixed cumulative full-batch and ordered exact
call-registration digests. Context and original client root are bound. Worker,
owner and attachment epochs and later effect knowledge do not change the witness.
The host receives its expected client root separately from the witness and checks
the committed prefix itself. This proves trusted local consistency and actual
client storage, not arbitrary remote persistence or downstream app display.

A nonterminal receipt can advance the existing volatile delivery assertion and
cannot retire content. A complete terminal receipt selects its canonical
`durable-receipt-v1:<digest>` fingerprint in the existing S82 keyless retirement
transaction. No new ledger or host schema exists. Lost replies retry the retained
fingerprint under the original ticket/caller without requiring deleted replay or
a live attachment. Other cancellation/expiry tombstones remain distinct. Private
publication retains current authorization and original-deadline checks after IO.

Client unbegun/unknown/known tool obligations survive host retirement until original
client expiry. A lost intent or outcome reply never grants another invocation.
The independent fake-effect counter belongs to the surviving supervisor; no real
tool runs, and no universal exactly-once claim follows.

Control messages are bounded to 2 MiB and individual replay messages to 12 MiB,
with a class byte and length checked before body allocation; raw batches remain
bounded to 8 MiB. Keys, tickets, context, replay and outcome bytes stay in memory
and owned anonymous pipes, never argv/env/plaintext fixtures or retained logs.
Only the host depends on MLX. One native host may coexist with one CPU client;
builds/tests/native workers are serial, with at most four build jobs. Original
journal limits remain unchanged; combined fixture/scratch limits and tiny MLX
observations are separately checked by the supervisor.

New evidence is focused local integration, current-authority/receipt refusals,
active ordinary native continuation, and actual host/client worker deaths. It
reuses unchanged S72–S83 native route/codec/Llama/ownership/credit campaigns rather
than multiplying them across the join. Resource samples are boundaries, not
continuous peaks or exhaustive descendant history. Corrupt or missing authority
never becomes a new empty journal.

Production app/auth/keys, wire/EvAck/runtime/pins, real tools, network/listeners,
EXO, device/VM/reboot/power-loss/hostile rollback, release and later phases remain
excluded. Keeper remains Held; physical work is deferred.
